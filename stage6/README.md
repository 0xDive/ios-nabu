# iOS-nabu Stage 6 — read-only boot-time FDT survey

**В этом образе НЕТ XNU / iOS.** Он **не проверяет выполнение XNU**. Его задача — проверить один из блокеров запуска ядра: описание памяти именно в Device Tree, который ABL передаст нашему диагностическому коду при временном `fastboot boot`. Запись в физическую память под XNU **отсутствует**.

## Что проверяет

- Идентификатор `NABU`, PSCI >= 0.2 и метод `SMC` / `HVC` на входе ABL.
- FDT: корректный заголовок, узлы `memory`, `reserved-memory`, `/chosen/linux,initrd-{start,end}`, таблица `memreserve`.
- Содержится ли **расчётный, НЕ подтверждённый свободным** диапазон `0x100000000 .. 0x1024D0000` внутри одного банка оперативной памяти.
- Пересекается ли он с *фиксированными* резервированиями, самим FDT и ramdisk.
- Есть ли динамические резервирования с размером, но неизвестным физическим адресом.

Даже если всё кажется чистым, это **не доказывает**, что диапазон свободен: DRAM могут занимать ABL, работающие подсистемы, стек, DMA, невидимые резервирования и firmware. Данные не сохраняются и не выводятся на экран.

## Сигналы автоматической перезагрузки

Время приблизительное и отсчитывается от начала исполнения ARM64-кода (после `Booting OKAY`). Сигнал — **самостоятельная** перезагрузка через PSCI:

| Время | Значение |
|------:|----------|
| ~8 с | FDT, память и известные резервирования прошли статические проверки, динамических узлов не найдено. **Не равно безопасной RAM.** |
| ~16 с | Статические проверки прошли, но присутствуют динамические резервирования без физического адреса. Это ожидаемо по FDT Android, где таких узлов 7. |
| ~28 с | Обнаружено пересечение расчётной области с fixed reserved, memreserve, FDT или ramdisk. Операции копирования запрещены. |
| ~40 с | Переданный FDT не соответствует ожидаемой схеме или не содержит подходящего банка RAM / описания ramdisk. |
| Не перезагрузился | Проблема раннего исполнения, FDT/PSCI или зависание. По одному чёрному экрану нельзя сделать вывод. |

Этот тест можно использовать только **после** прохождения read-only `preflight.ps1`, на разблокированном `nabu`, с резервной копией данных и возможностью выключить планшет кнопкой питания. **Никаких `fastboot flash`.** Не запускать `nabu-stage6-fdt-survey.img`, если имя/хеш не совпадает с этим архивом.

## Проверки на Windows

В режиме Android:

```powershell
adb reboot bootloader
```

В распакованной папке Stage 6:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\preflight.ps1 -Image .\out\nabu-stage6-fdt-survey.img
```

Если вывод `PASS`, временный (не прошивающий разделы) запуск:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\preflight.ps1 -Image .\out\nabu-stage6-fdt-survey.img -Boot
```

Требуется подтверждение `BOOT`. **При зависании не ждите бесконечно:** удерживайте питание около 15–20 секунд. Не повторяйте тест до разбора результата. Не используйте фиктивные/непроверенные адреса framebuffer.

## Воспроизводимость

На Linux с `clang`, `ld.lld`, `llvm-objcopy`, `nm`, `readelf`, Python 3:

```bash
bash build.sh
python3 -m unittest discover -s tests -v
```

Образ `boot.img` версии 3, компилируется из исходников в `src/` и использует пустой архив initramfs. Для минимальной исследовательской полезной нагрузки недостаточно просто собрать XNU Mach-O: далее требуются безопасное реальное расположение памяти, адаптированный загрузчик ядра и отдельный канал логирования.

Тесты сканера сгенерированы синтетически, а предоставленный пользователем реальный `nabu.dtb` проверен локально и **не должен попадать в публичный репозиторий**.
